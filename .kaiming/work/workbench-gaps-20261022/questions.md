# U4 / U5 的决定

日期：2026-10-22。原问题见下方「决策前的选项」；决定采用**简单形态**，实现与验证已完成。

## 决定（用户 2026-10-22 确认）

| 项 | 决定 | 实现 |
|---|---|---|
| U4 恢复核实 | 简单处理：**继续会话，让主管决定**。界面不重放、不代答 | 会话空闲时读一次 `session.recovery.inspect`；有未核实输入时显示横幅（数量 + 输入 id），「让主管核实」把请求填进 composer，用户可改写后再发送；`resolve` 无界面，处置由主管的 `task(op=recover)` 执行 |
| U5 会话清理 | **会话列行内清理**，两步确认 | 行内「×」→「确认删除？」；CAS 用行上的 `revision`；当前会话不提供该动作；被拒绝时把服务端 `gaps` 原样列出（例如仍在排队的输入、被 Task 引用） |

## 保留的边界

- 横幅只在会话空闲时读取：运行中的会话仍可能自己关闭输入，提前宣布「未确认结束」是错的。
- 被中断的输入不会因显示横幅而改变状态；服务端仍是 `interrupted`，直到主管核实。
- 清理是删除会话及其输入/绑定，**不动**项目文件、需求、任务与报告；被引用的会话一律拒绝。
- 删除没有撤销：因此需要两次点击，且当前会话不可删。
