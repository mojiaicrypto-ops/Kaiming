# 测试责任规则 Plan

类型：已授权产品交付规则与角色提示词维护。用户明确要求：E2E/端到端集成验收优先于单元测试；开发 Agent 内置单元测试及 TDD，测试 Agent 负责 API 集成与 UI E2E。

范围：D-05 为唯一产品责任定义；开发/测试及主管/Review 提示词按职责执行；G1/G4更新测试责任与上下文；I4及产品验收增加可观察场景；导航/验证记录按证据维护。沿用当前适用Test、Review后Test、候选一致、角色权限和真实报告，不新建测试对象、类型Schema或程序门禁。

上下文：AGENTS/索引、产品交付与验收、G1/G3/G4、当前角色提示词、I4。排除旧实现/旧方案作为规则。完整规范仍按现有产品/技术入口引用。

步骤：根Agent单独修改 → 干净上下文独立只读审阅 → 静态链接/正文装配/跨文档规则核对 → 修正具体发现 → 审阅、验证、结算归档 → 仅提交本次文档。

完成：开发的单元/TDD与独立端到端验证分工明确，API/UI场景可执行，单元或Mock通过不被当成端到端通过；环境缺失如实blocked/not_run。文档规则完成不等于已实现或实际运行测试。
