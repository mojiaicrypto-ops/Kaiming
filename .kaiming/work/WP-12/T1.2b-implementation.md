## 1. 逐文件变更

### `apps/web/src/views.ts`

- 新增 `ProviderModelView`（`id`/`contextWindow`/`maxOutputTokens`/`reasoningLevels`/`vision`/可选价格）与 `ProviderEditorView`（Provider 行 + `models`）。
- `SettingsModel.providers` 改用 `ProviderEditorView`，并新增模块内 `providerModelViews()`：**逐字段白名单**投影，`secretRef`/`apiKey`/`secret` 等键永远不会进入页面模型（`protocol.md` §5：`secretRef` 由服务端创建、值不回显）。
- 新增导出纯函数 `providerModelsInput(models)`：生成 `ProviderInput.models` 时省略未声明的可选价格（`providerInputSchema` 里它们是 `.optional()` 而非 nullable，写 `null` 会被 daemon 判 `VALIDATION_ERROR`）。

### `apps/web/src/pages.ts`

- 新增 `renderProviderEditor()`：每个 Provider 一行一个 `<form class="provider-form" data-provider data-new>`，字段与控件见 §2；`连接测试` 的模型下拉受持久化的 `models` 驱动，无模型时下拉与按钮 `disabled` 并给出 `settings.testNeedsModel` 提示。
- `renderSettingsPage` 的 Provider 行在摘要 chips 后嵌入该编辑器；`settingsProviders` 面板末尾**始终**渲染「新增 Provider」表单（`data-new="true"`，`providerId`/`baseUrl` 为空、`models` 为 `[]`），因此零 Provider 的安装也有入口。
- 结果区 `<div class="provider-result" hidden>` 与服务端已渲染的 `data-i18n` 文案：客户端只切换 `hidden`，不拼英文串，语言切换时这些句子仍随字典走（daemon 的 `ui.translate` 目录是另一份列表，见 §4 缺口 3）。

### `apps/web/public/app.js`

- 新增纯函数 `providerUpsertParams(input)`：校验 `type ∈ {openai-compatible,anthropic,google}`、`baseUrl` 非空、`models` 是 JSON 数组；`providerId` 为空则**不带该键**（交给服务端创建）；`secret` **仅当长度 > 0 时**写入 params。返回的 params 是值唯一去处。
- 新增纯函数 `providerTestOutcome(data)`：从 `provider.test_completed` 的 `data` 保守读取 `accepted`/`ok`/`latencyMs`/`error`；无法分类时 `accepted: null`，绝不渲染成成功。
- `initProviderEditor(editor)`：提交走 `rpc('provider.upsert', {provider, secret?})` + 幂等键；失败 `showProviderError(editor, error, true)`（表单/密钥输入原样保留）；成功只显示 `secretConfigured: <bool> · version <n>`，随后清空密码框，并用刚保存的 `models` 重填测试下拉、回填服务端创建的 `providerId`。
- 连接测试：`rpc('provider.test', {providerId, modelId})` → 展示「已接受 + 结果稍后到达/查看 Runs 或事件」；若命令直接回 `accepted:false`，渲染为不可用（不谎称在跑）；`provider.test_completed` 到达时按 `data.providerId`（回退 `frame.entityId`）找到编辑器，渲染 `testCompleted` + 可用/不可用 + 细节。
- `initSettings()` 重构：`configForm` / `configTest` / `test-provider`（Agents 页）/ `provider-form` 各自独立绑定（原来 `if (!form) return` 会让 Agents 页的测试按钮永远不绑定；行为上只增不减）。
- WS 打开页面集合增加 `settings`，复用既有 summary 订阅 + 水位续订。

### `apps/web/src/app.ts`

## 2. 表单契约

每个 `form.provider-form`（`apps/web/src/pages.ts::renderProviderEditor`）：

| 控件 | 选择器 | 说明 |
|---|---|---|
| Provider id | `[data-field="providerId"]` | `ProviderInput.providerId?`；空 = 新建 |
| 类型 | `[data-field="type"]` | `providerTypeSchema` 三值 |
| Base URL | `[data-field="baseUrl"]` | `z.string().url()` |
| 启用 | `[data-field="enabled"]` | `checkbox` |
| 模型 | `[data-field="models"]` | `ModelDescriptor[]` 的 JSON 文本（`data-translatable="false"`） |
| API Key | `[data-field="secret"]` | `type="password" autocomplete="off" data-translatable="false"`，**永不回填** |
| 保存 Provider | `button.provider-save` | 提交 `provider.upsert { provider, secret? }` |
| 测试模型 | `select.provider-test-model` | 来自持久化 `models[].id` |
| 连接测试 | `button.provider-test` | `provider.test { providerId, modelId }` |

- **空密钥语义**：`secret === ''` → params 中不含 `secret`（保留既有凭证）；非空 → 原样发送。不做 trim（真实密钥可能含空白），只判长度。
- **保存成功**：只渲染 `secretConfigured: <bool> · version <n>`（键名是协议字段，非 UI 文案），并清空密码框。
- **保存失败**：`<p data-role="error">` 显示 `<code>: <message> — input preserved`，所有输入（含密码框）保持原样。
- **连接测试**：命令只回答 `accepted`；结果靠持久事件 `provider.test_completed` 回填。事件未达时固定显示「结果稍后到达/查看 Runs 或事件」。
- **硬规则**：密钥值只存在于 `providerUpsertParams` 的返回对象与 `/rpc` 请求体中；不写 `data-*`、不写 `textContent`、不进页面模型、不进 HTML。`apps/web` 源码中无任何 `console`/`stderr` 输出，故也不可能进 BFF 日志。测试用「保存后 HTML + 序列化模型」grep 负例守住该规则。

## 4. 已知缺口 / 未做（诚实清单）

1. **daemon 的 `provider.upsert` / `provider.test` 是并行切片**：本人按 `protocol.md` §5 契约写 UI，**没有**任何「命令不存在就假装成功」的兜底；命令未落地前，点击保存/测试会原样显示 daemon 的协议错误码与消息（诚实失败）。BFF 转发只用一个记录型 fake upstream 验证（`server.test.ts`），**未**对真实 daemon 跑这两条命令。
2. **`provider.test_completed` 的端到端未验证**：事件名与「持久事件」地位见 `protocol.md` §5/§7，但事件 `data` 的具体字段（`accepted`/`ok`/`latencyMs`/`error`/`providerId`）文档未固定，客户端按防御式读取；无法分类时不渲染成功。summary 订阅是否投递该事件由 daemon 决定，未实测。UI 始终同时给出「结果稍后到达/查看 Runs 或事件」，因此事件即使不到也不会假装完成。
3. **`config.test` 与 `provider.test` 并存**：`config.test { role }` 是既有的「角色 Profile 是否可用」命令，Agents 页与 Settings 的 `configForm` 仍用它；新的**连接测试**按 §5 用 `provider.test { providerId, modelId }`。二者回答的问题不同（角色可用性 vs 单 Provider+模型连通性），本刀未删 `config.test` 入口，也未把新按钮降级成 `config.test`。是否需要合并/改名，**待决策**。
4. **新建 Provider 需要先保存再测试**：`provider.test` 要 `modelId`，而模型列表来自持久化文档，所以新建表单在保存前测试按钮为 `disabled` 并提示 `settings.testNeedsModel`；保存成功后客户端用刚提交的 `models` 即时启用。这是有意取舍，不是缺陷。
5. **保存 Provider 后不刷新 `settingsMeta` 的活动版本/版本 chip**：`provider.upsert` 返回的 `version` 语义（Provider 版本还是配置 revision）文档未明确，故只在编辑器内显示该 `version`，不冒充 `config.get` 的 `revision`。若 daemon 确认二者一致，可再加联动——**待确认**。
6. **`ui.translate` 目录不含新 key**：daemon 的字符串目录是 `apps/daemon/src/protocol.ts` 内另一份 `UI_STRINGS`（不在本刀范围）。为避免动态状态串落到英文 fallback，结果句全部由服务端预渲染的 `data-i18n` 节点表达，客户端只切换 `hidden`；既有 `configForm` 的 `state.strings[...] || 'saved'` 行为未改。若要让 `ui.translate` 也覆盖新 key，需要在 daemon 侧同步目录（跨切片）。
7. **`pendingProviderTests` 只在事件到达时清理**：事件永不到达时该 Map 会保留一个编辑器引用（每次点击一条，生命周期为页面）。P3，未处理。
8. 未运行 `git commit`/`git add`；改动全部留在工作区，本文件即证据。未修改 `docs/**`（`docs:check` 通过）。
