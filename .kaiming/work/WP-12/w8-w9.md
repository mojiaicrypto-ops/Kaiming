## 1. W8-1：`checkResult.environmentRef` 与 `VerificationManifest.environmentRef` 统一

**问题**（`test.md` 指出、`w5-test-execution.md` §157 登记）：Test 的已执行证据里 `checkResult.checks[].environmentRef` 写的是 **Attempt id**，而冻结的 `VerificationManifest.environmentRef` 写的是 Runner 自报的 **描述串**（`host:<platform>/<arch>/node-<major>` / `container:<image>`）。两者被文档描述成同一件事（"验证运行在哪个环境"），实际却一个是 id、一个是描述串，读者必须做一次映射才能比对；`w5` 当时的理由是 `data.md` §3 把该字段类型写作 `ID`。

**处置**：按裁决取"manifest 用的真实环境描述串"，两处同值。

| 改动 | 文件 |
|---|---|
| 新增共享契约 `environmentRefSchema`（非空描述串；显式注释说明为何不再是 UUIDv7） | `packages/contracts/src/primitives.ts` |
| `checkEntry.environmentRef`、`verificationManifestSchema.environmentRef` 由 `idSchema` 改为 `environmentRefSchema` | `packages/contracts/src/entities/structures.ts` |
| `attempt.ready` 的 `environmentRef` 改用同一 schema（原来就是 `z.string().min(1)`，现在两处同源） | `packages/contracts/src/runner-ipc.ts` |
| 生产者：check 的 `environmentRef` 取该 Attempt 的 `attempt.ready` 描述串（原先取 `attemptId`；描述串缺失时保留 Attempt id 作为 fail-closed 兜底，而该兜底下候选提交会因 manifest 无环境而拒绝冻结） | `packages/core/src/execution.ts` |
| `TestCheckResultInput.environmentRef` / `executionImage` / `runnerEnvironment` 的文档语义同步 | `packages/core/src/test-environment.ts` |
| `data.md` §3 的 `CheckResult`/`VerificationManifest`：`environmentRef:ID` → `environmentRef:Env`，并新增 `Env` 定义（两处必须同值） | `docs/architecture/data.md` |

**一致性用例的意义与边界**：生产中两处读的是**同一个** `Supervisor.environmentRefOf(attemptId)`（`execution.ts` 给 check，`control-handler.ts:293` 给候选 manifest），因此"同值"是构造性的；该用例把这条不变量固定在库级并顺带证明契约真的接受描述串。Runner 真实产出该描述串的端到端证据仍由 `pnpm test:live` 的 `drill.message-to-stage` 提供（本次 PASS，`checkResult` 证据串中的 `runner=host:darwin/arm64/node-24`）。

## 2. W8-2：临时流写进 `protocol.md` §7

`token.delta`、`log.delta`、`heartbeat` 原先只有一句"为临时流……不占持久 cursor"，但 §7 的事件表紧接着列出持久事件名，容易被读成"这三个也必须作为持久事件发射"（`api-gap-audit-2.md` §3.2 判定三者从未发射）。

现在 §7 明确写：它们是**连接内的内部流式通道**，**不在**持久事件清单内，不落 `event` 表、不占 `cursor`、不参与 `events.subscribe` 回放与水位；实现不得把它们当必须发射的持久事件，验收也不以"是否发出这三个名字的持久事件"为判据；当前实现的 WS 持久通道帧是 `hello`/`event`/`batch_end`/`response`，`attempt.heartbeat` 是 Runner 父子进程 IPC。**无行为变更。**

新增 `scripts/lib/acceptance-levels.mjs`，由 `scripts/acceptance.mjs` 在判定完成后逐 AC 调用。层级**全部从本次运行实际产生的证据推导**，没有逐 AC 手填：

| 层级 | 推导规则 |
|---|---|
| `product-path` | 该 AC 有真实发布演练（`pnpm test:e2e` = 真 daemon + 真 Runner 子进程 + 真 Chromium；`pnpm test:live` = 真 Provider）的逐 AC `PASS` 行，**或**提交套件里有已执行的 `apps/*/test/**` 应用层用例（`api-gap-audit-2.md` §4 与 `test.md` §3.7 同用的层级定义），但排除播种行 |

| `unclassified` | 既无已执行套件证据、也无已执行演练行；报告显式标出，不猜 |
