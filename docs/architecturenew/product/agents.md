# Agent 规则装配需求

实际文本是本套需求的一部分，见 [规则目录](rules/INDEX.md)。规则标识及工具名字必须与 [工具契约](contracts.md) 一致。

主管 Agent 是用户的主对话伙伴和专业 Agent 的协作组织者，职责贯穿自由讨论、需求澄清、任务组织、调度协调、进展跟进和结果反馈。主管根据用户当前意图决定直接讨论、调查或组织专业协作；只有明确进入正式交付才启用相应流程。内部角色标识为 chief。

## AGT-01 主管启动包

按以下顺序实际注入正文：Server 规则版本与项目身份 → [core](rules/core.md) → [chief](rules/chief.md) → [规则索引](rules/INDEX.md) → 受信项目 AGENTS.md → 当前用户输入（含真实 inputRef）或恢复摘要。系统恢复通知不能冒充用户授权。

启动包包含 `.dev/INDEX.md` 位置、规则根位置、task 查询入口，不自动加载全部产品/技术文档。core 固定正文不被项目指令覆盖；项目补充规则可提高要求，不能取消必需独立验证、真实结果与结算。未信任时不注入项目 AGENTS 或扩展。

目录中列有规则不等于读过正文。写需求前读 knowledge；开始交付前读 delivery；结算前读 settlement。用户自由讨论不强制读完这些文件。

## AGT-02 子 Agent 启动包

按顺序注入 core 正文 → roles 中对应角色章节 → 规则索引 → 受信项目 AGENTS → 主管提供的任务说明。主管可以给丰富自然语言、文档/代码路径、调查结论、依赖和未知，不规定细密上下文字段。

任务说明至少让角色知道目标、范围、相关规则/需求/Plan 路径、交付期待及未知；子 Agent 可沿索引自主调查，不要求主管预读每份依赖全文。所读取正文及理由可以记入阶段报告，不另建上下文审批系统。

Review/Test 的任务输入由角色装配约束：没有开发/主管 transcript 或自评，只保留目标、正式依据、实际 diff/source、真实证据与适用配置。Server 不给它们其他 Session 的聊天读取工具；主管不能通过上下文文本绕过。审核者可质疑主管结论。

## AGT-03 角色与工具

| 角色 | 可用职责 | 工具限制 |
|---|---|---|
| chief | 自由讨论、理解意图与澄清需求、知识导航、任务组织、调度协调、进展跟进、结果反馈及交付收口 | task/agent/user/project_ready/project_publish 工具；文件用于已确认初始化入口、需求文件（含正文）及需求入口、计划，不替代专业实施/验证 |
| product / planning | 产品/知识整理与规划 | 授权文档读写、只读调查、agent_result |
| frontend / backend | 对应实施与范围内修复 | 工作区文件/命令、agent_result；不能自行提交验证通过 |
| review | 独立检查与 Findings | 源码只读，允许执行检查和写任务证据；不修改被审核文件 |
| test | 独立行为验证与回归 | 源码只读、隔离临时环境/证据目录写入、真实命令、agent_result |
| settlement | 知识回填、归档、发布记录 | 项目知识及本 task 证据读写、agent_result；不修改产品代码 |

只读不是“禁止一切命令”：检查可运行，必须使用临时输出/测试环境。测试副作用由项目检查配置和执行工具约束；默认不得操作生产数据/服务。权限确认接口见协议，第一版不实现复杂能力编排平台。

专业角色只提交结果或向主管请求帮助，无权直接创建其他专业 Session。调查可以不关联 task；正式阶段必须关联 task/step。角色配置解析见 project.md，全部实际配置随 Session 记录。

## AGT-04 恢复和规则版本

恢复指定 Session 时读取其 Pi 文件，并在下一模型轮装配当前有效规则、项目入口和 task 摘要。不得把仅存在的旧聊天当成任务状态。规则版本改变时留下版本记录，需改变正在执行任务范围/授权则阻断并请求用户决定。

有可用会话文件使用指定会话续接；新角色/审核永远新建 Session。无文件的新主管接续只拿 task/结果/项目知识引用，授权来源仍可追溯，未知执行先核实。

## AGT-05 输出与显示

模型文本用于说明，agent_result 用于持久阶段结果；task_finish 用于最终完成。工具返回内容真实失败时不能换成“应该成功”。

用户可以查看主管消息、专业结果和工具过程。显示专业聊天不代表这些内容可以注入另一角色。没有模型也保留并展示记录，不伪造调查与审核。

验收：AC-A01～AC-A04、AC-T03、AC-T05、AC-R01。
