# AgentDev 产品需求文档

版本：0.3。日期：2026-10-02。状态：可实施的产品需求建议稿，等待整体评审与批准。本文定义目标行为，不声明功能已经实现。

## 1. 用户问题与完成目标

用户希望自由讨论和推进软件项目，但跨会话需要反复解释需求、技术事实和开发进度；Agent 容易将讨论当成需求、将自己的总结当成验证，并在交付后留下过期文档。

AgentDev 将用户的明确工作交给主管 Agent，由主管选择知识、组织专业 Agent、完成独立验证和结算。完成后，用户能看到实际结果、证据和剩余问题；新会话能从项目文件了解当前事实；中断后能找到任务已完成和未完成的部分。

第一版面向单用户、多项目、Server 持续后台运行的研发工作台。浏览器关闭不停止工作。模型调用仍需要配置的 Provider；没有模型时可以查看项目文件与任务记录。

## 2. 第一版交付范围

必须实现以下闭环，缺少任何一段都不能作为完整产品交付：

1. 打开目录，绑定项目，查看或创建独立主管会话。
2. 自由讨论；明确保存后，按内置规则写入模块化需求与知识。
3. 明确实施后创建持久 task；主管自主计划、派发和返工。
4. 标准代码交付经过独立 Review、独立 Test；轻量修改和纯文档经过独立检查。
5. 结算更新知识、索引、需求摘要和证据归档，完成工具核对流程。
6. 浏览器断线后刷新真实状态；Server 重启后接续已知进展，未知副作用先核实。

第一版使用宿主工具执行。工具接口接收明确工作目录；远程、容器可在相同工具接口下增加实现。当前版本不实现分布式执行、多人权限、自动工作流编译器或自动定时清理。

## 3. 产品责任划分

| 责任 | 执行者 | 产品要求 |
|---|---|---|
| 理解讨论、文档归属、需求拆分、任务组织、上下文与返工 | 主管/专业 Agent | 使用本文提供的规则，自主调查，提出产品选择和未知 |
| 文件读取/写入、需求解析、task 与结果持久化、身份隔离、真实工具执行 | 程序 | 明确返回成功、失败或未知；不得从自由文本推断完成 |
| 产品目标、范围、规则变化及风险接受 | 用户 | 明确表达或答复 action；已存在的授权不重复索取 |
| 按钮排版、页面布局、颜色和交互呈现 | 客户端 | 消费消息与 action 契约，不能自行改变任务或需求事实 |

需求只有项目文件一份权威。task 只记录执行现场与引用，不复制需求正文。Session 是独立 Pi 会话；第一版不再增加 Conversation 或自有 Run 业务对象。Pi 的单轮运行事件仍原样传递。

## 5. 本稿采用的明确选择

| 选择 | 第一版行为 | 理由 |
|---|---|---|
| 项目身份 | Server 生成稳定 projectId，以 realpath 查询；移动目录由用户显式重绑定 | 不猜测同名/Clone 是否同一项目 |
| 会话身份 | sessionId 与一个 Pi Session 一对一；专业角色新建 Session | 减少对象，保持独立审核 |
| 文档根 | 项目根 `.dev/`，根 AGENTS.md 放入口和项目参数 | 位置确定，模块内容由 Agent 自主组织 |
| 需求格式 | 单 Markdown 文件，固定 YAML 元数据，正文按模板 | 程序读少量字段，AI 负责内容 |
| 无预先保存需求的开发指令 | 标准任务先由 Product 整理交付需求，原开发指令保留为启动授权；轻量任务不建需求 | 确保有验收，又不要求重复点击 |
| task 更新 | 创建/计划/派发/结果/暂停/完成工具自动更新；只有补充阻断/下一步使用 task_note | 不要求主管每一步额外调用 task.update |
| 计划授权 | 明确实施指令预授权范围内计划；超范围/规则/风险变化先询问 | 尊重用户指令，保持流程可核对 |
| 恢复 | Pi 保存会话；程序保存 task/结果/未处理输入。未知工具副作用阻断，不能承诺任意命令恰好执行一次 | 有恢复基础，不自建通用调度平台 |
| 保存与提交 | 先写项目文件再尝试独立 Git 提交；结果区分本机保存与 Git 提交 | 不引入另一份需求数据库 |
| 清理 | 不自动删除；用户显式清理已结束会话，不能删被有效任务引用的记录 | 第一版行为明确且可逆风险可控 |

这些选择是可审阅的具体建议。若用户调整其中一项，修改对应需求、规则和验收；实现者不能自行换成其他行为。

## 6. 实施批准边界

全部条目为第一版必需。规则编号标识产品约束，AC 编号标识可观察验收；用例通过才是实现证据。

技术 Plan 可以选择模块、数据库索引、工具库及锁定的 Pi 版本，但必须保持本文行为。Pi SDK 适配需要通过实施单元 I0 的实际探针；不能用文档说明冒充运行验证。

当前完成的是需求建议稿；整体批准、代码实现与验收执行是后续工作。
