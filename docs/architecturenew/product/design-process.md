# 产品需求维护流程

当前实施入口是 INDEX.md。本文用于修改需求，不要求开发者重新展开产品发现。

1. 先检查用户旅程：打开项目→讨论→保存→实施→验证→结算→接续。
2. 将一项改变写到最近职责文档，同时更新适用规则正文、工具/格式、模板和验收。
3. 产品文档明确触发、输入、正常结果、异常、状态与完成条件；字段/目录/工具名不得用待决占位。
4. 独立评审只依据本套文档与样例，不靠作者聊天补定义；测试实现需要实际证据。
5. 用户批准明确的行为建议后形成实际代码 Plan，按 implementation.md 的依赖推进。
6. 产品选择改变回到需求文档；技术实现选择留在 Plan。不让实现者用历史材料填补本套行为。

第一版需求已采用 INDEX.md 的具体选择；它们仍是待整体批准的建议，没有未定义的产品选择留给工程师自行处理。剩余技术工作是依赖锁定、模块/SQL/库适配和代码 Plan，不是补定义产品流程。
