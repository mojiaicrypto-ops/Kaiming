# 待办文件格式

本页是待办文件序列化、解析、容错与引用解析的唯一权威。待办的业务含义、直接编辑和修复方式见[待办与规格 BL-02～BL-03](../productnew/modules/backlog-and-specs.md)；模型工具及访问权限见 [G2 backlog](agents-and-tools.md)。格式检查不判断一条待办是否值得实施、拆分是否内聚，也不判断关闭说明写得是否合理。

## BF-1 位置与整体结构

一个项目一份 `.dev/backlog.md`，UTF-8 Markdown。文件不存在表示没有待办；`add` 在文件不存在时创建它。文件由两级标题组织：

```markdown
# 待办

以 `### 编号 标题` 开头的一条是一件事；`- 状态:` 只能是 open / done / dropped。
改坏了会在项目页显示位置和原因；修复只需改原文。

## 未完成

### B-12 部分退款
- 状态: open
- 规格: .dev/product/refund.md#部分退款
- 来源: chief s-1a2b3c4d / i-5e6f7a8b
- 创建人: local
- 创建: 2026-11-07T10:00:00Z
- 更新: 2026-11-07T10:00:00Z

用户希望支持按商品行部分退款；依赖 B-11（交易记录可按行查询）。

## 已关闭

### B-3 登录页错别字
- 状态: done
- Task: t-12ab34cd56ef
- 说明: 已在 t-12ab34cd56ef 交付
- 来源: 界面
- 创建人: local
- 关闭人: local
- 创建: 2026-11-01T09:00:00Z
- 更新: 2026-11-02T08:00:00Z
- 关闭: 2026-11-02T08:00:00Z

（正文）
```

- **开头说明**：`# 待办` 之后的几行自由文字是给人看的书写约定，不是条目；工具不改写它。新建文件时写入上例中的三行说明。
- **分节**：「未完成」放 open，「已关闭」放 done / dropped。分节由程序按 `状态` 决定；**读取时以状态字段为准**，不看条目所在分节。
- **排序**：未完成的条目按创建时间倒序，已关闭的按关闭时间倒序。排序只影响新增和状态变化时的位置，不改写其他条目。
- **不因状态拆文件**：编号、标题和原文件位置在创建后不变。

## BF-2 条目语法

- **条目范围**：一个条目以三级标题 `### <id> <标题>` 开始，到下一个三级或二级标题、或文件结束为止。
- **元数据与正文**：标题下面连续的 `- <键>: 值` 行是元数据；未知键（例如 `- 优先级: 高`）保留在原位、原样写出，但不解释，键集合也不因此扩大——它不会终止元数据块，写在它后面的 `- 状态:` 仍然生效。遇到第一行不是这种形式的内容，后面都是正文。
- **必需字段**：只有编号（来自标题）和 `状态`。其他键都可以省略；工具写入时自动填写来源、操作者和时间。
- **多值与重复键**：`规格` 和 `Task` 是多值键，每行一个值，重复出现时按出现顺序累积为数组；写出时每个值一行。同一行里的逗号是值的一部分，不做拆分。单值键重复出现时：`状态` 重复是**问题**（无法判断状态）；其他单值键重复是**警告**，取第一次出现的值。
- **元数据键**：固定集合，中英文都接受：

  | 中文 | 英文 |
  |---|---|
  | 状态 | state |
  | 规格（可多行） | spec |
  | Task（可多行） | task |
  | 来源 | source |
  | 创建人 | createdBy |
  | 关闭人 | closedBy |
  | 创建 | created |
  | 更新 | updated |
  | 关闭 | closed |
  | 说明（关闭说明；工具参数 `note`） | note |
  | 外部 | external |

  程序写出时沿用条目里已有的语言；新建的文件用中文。
- **`外部` 键**：保留位置，格式为 `<provider>:<id> <url>`。本阶段只解析、原样保留，不使用。
- **`状态`**：取值只能是 `open`、`done`、`dropped`。
- **时间**：一律用 UTC 的 RFC3339 格式。
- **`规格`**：使用 BF-5 的引用格式。写入时核对引用是否存在；不存在只警告、不拒绝，因为设计可能先记待办、后写规格。
- **`说明`**：关闭时工具要求写说明（`close` 的 `note` 必填）；直接编辑漏写只给警告（BF-3）。重开时写明原因。
- **`Task`**：只作追溯，可多行。设计产生的切片记录产生它的设计 Task，实施/结算关闭时再追加交付它的 Task；读取时不校验该 Task 是否存在，新环境里缺失时界面把关联显示为缺失，不改变条目状态。设计切片的未结束设计 Task 决定它是否可实施。
- **标题**：编号之后直到行尾的文字都是标题，不解析其中的符号；标题可以为空以外的任意文本。

## BF-3 解析与容错

- **只按行处理**：解析从不执行文件内容。
- **结果分三类**：

  | 输入 | 结果 |
  |---|---|
  | 标题合法，`状态` 为 open / done / dropped | 正常条目 |
  | 标题合法，但缺少 `状态` 或值不合法 | **问题** |
  | `###` 标题，但开头不是合法编号（例如 `### 导出 CSV`） | **问题**：无法识别编号 |
  | `##` 标题，开头是合法编号（例如 `## B-12 …`） | **问题**：标题级别应为 `###` |
  | 同一个编号出现多次 | **每一次出现都**是问题 |
  | `状态` 出现多次 | **问题** |
  | 时间格式不对；`规格` 指向的位置不存在；状态为 done / dropped 却没有 `说明`；其他单值键重复 | 正常条目，附**警告** |
  | 元数据块中不认识的键、条目之外的文字、注释、其他标题 | 原样保留，不报告 |

- **文件级问题**：文件有非空白内容，却一个条目都识别不出来、也没有任何问题时，返回一条文件级问题“未识别出任何条目，可能格式已被改动”，界面不显示为“没有待办”。
- **问题的后果**：有问题的条目不能被领取，也不能通过 `add` / `close` 或界面的修改、关闭、重开去操作；其余条目照常。问题和警告都附带行号、原文片段和原因，**既不隐藏，也不丢弃**。
- **不自动修复**：程序不猜测意图，不改写有问题的条目。修复方式是改条目原文：用户在编辑器里改，模型用 `backlog(op=edit)` 改。原文修好后，下一次读取时问题自然消失：
  - 重复编号：已被 Task 关联或被其他条目引用的那一条保留原号，另一条改为当前最大号加 1；分不清哪条是哪条时，主管先请用户决定；
  - 其他问题：按原因补齐或改正。
- **其他文字原样保留**：分节标题、注释、条目之外的文字都不改动。
- **写出时最小改动**：只移动本次操作改到的那一条，其他条目的原文不重排、不重写。直接编辑的内容与工具写入的内容在同一份文件里共存。
- **原子写入**：同目录临时文件加 `rename` 替换，随后读回核对；失败时原文件不变，也不残留临时文件。

## BF-4 编号

- **编号是不透明字符串**：核心代码把条目 id 当作不透明字符串，可接受的形式是 `^[A-Za-z][A-Za-z0-9]*-[A-Za-z0-9_-]+$`。除下一条的本地分配，任何代码都不解析其中的数字。
- **本地分配规则**：新编号为 `B-<n>`，`n` 等于文件中现有 `B-` 编号的最大值加 1。已关闭的条目，以及损坏但编号能读出来的条目都参与计算。分配在项目锁内进行。
- **不变、不复用**：编号创建后不再改变，也不会被重新使用。唯一例外是修复重复编号（BF-3）：其中一条改为新号，旧号仍然不分配给别的条目。

## BF-5 引用格式与解析

```text
<ref> := [<scheme>:]<location>[#<heading>]
```

- **前缀（scheme）**：不写前缀就是仓库内的项目相对路径。本阶段**只支持仓库路径**；带其他前缀的引用被拒绝，提示“不支持的引用类型”。
- **适用位置**：待办的「规格」、Task 的 `acceptanceRefs` 与 `basisRefs` 使用同一格式，经过同一个解析器。
- **接口**：

```typescript
interface ResolvedRef { ref: string; exists: boolean; text?: string; heading?: string; version?: string }
function parseRef(ref: string): { scheme: 'repo'; path: string; heading?: string };
function resolveRef(projectCwd: string, ref: string): ResolvedRef;
```

- **标题（heading）**：`#` 之后是目标文件中的标题文本，用于定位到具体行为；找不到时 `exists` 仍按文件是否存在，界面提示位置缺失。
- **版本（version）**：文件已被 Git 跟踪且没有修改时，取 Git 的 blob 哈希；其他情况取内容的 sha256。
- **外部引用**：非仓库引用本阶段不支持。将来支持时，Plan 的依据部分必须写下读到时的版本，因为外部文档没有 Git 历史；这条规则现在只写进文档。
