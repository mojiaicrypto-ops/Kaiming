# 产品验收

## 如何使用

本页检验用户能否完成实际工作，产品定义见 [总览](README.md)，操作过程见 [用户流程](journeys.md)。每项记录实际用户输入、可见结果、成果/资料和必要证据；文档检查通过不等于产品验收通过。

在同一开明实例的一个全局 Server 中准备三个独立项目：A 有代码和已有文档，B 为第二个项目，N 没有 Git。有可用模型，也测试模型不可用。每项场景独立准备，不能借用上一场景偶然留下的状态。接续场景要实际关闭、断线或重启，不能只改显示标签。

| AC-16 | 审核或测试发现当前目标缺陷；另提出范围外优化，用户选择以后做/不采纳 | 当前缺陷修复后重新独立检查；额外建议不扩当前承诺，用户同意后才记为待办；旧报告保留 | C-01、D-05、D-08、BL-02 |
| AC-17 | 开发聊天包含自称通过；查看审核/测试实际输入与依据；同阶段并行多个 Review；多人专业工作组合 | 独立角色没有开发/主管聊天自评，能查正式依据和真实成果；每项 Review 独立保存并汇总，未完成本轮审核与问题处理不启动 Test；修改不互相覆盖，最终组合有适用验证 ；等待范围只含当前 Task 当前步骤子 Session，排除主管和历史步骤；一份完成/阻断报告不提前返回，全员结束汇总全部报告/异常；超时返回状态且不取消，运行/排队/用户等待不重建，异常停稳后核实续办，用户暂停/取消不自动重启 | C-02、D-03、K-04 |
| AC-18 | 真实测试失败；另有环境导致部分未覆盖，用户未/已处置风险；必要 API 集成/UI E2E 环境缺失但单元已通过 | 失败返工，不能改称未覆盖；未执行不能通过，必要端到端环境缺失如实 blocked/not_run，不降级为单元或 Mock 验收通过；覆盖缺口、处置和证据可读，重大问题未解决不能完成 | D-05 |

## 整体交付检查

必须实际走通 [总览案例](README.md) 和 J-01～J-13，覆盖设计转化、标准、轻量、文档工作，以及从需求文档或已有代码起步、断线、暂停和接续。

用户最后应能回答：做了什么、检查了什么、没做到什么、成果在哪里、项目知识是否更新、下一次如何继续。任何一项只能靠作者口头解释，不能算完整可用。

结果分别记录通过、失败、未执行、环境阻断或明确允许的风险处置。测试夹具只能证明相应可靠性行为；主管能否合理组织待办、规格和知识，需审阅实际产物；完整用户流程需要实际可用模型和浏览器操作。未实现或未执行不能记通过。
