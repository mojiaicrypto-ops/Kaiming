# 项目工作区

## 用户目标与模块边界

用户将一个软件项目接入工作台，找到它的会话、需求、知识和正在进行的工作，之后随时回来继续。项目工作区负责接入、入口和基础设置；具体讨论见 [主管对话](chief-conversation.md)，正式交付见 [任务交付](delivery.md)。

## P-01 添加和重新打开项目

每个 AgentDev 实例只有一个全局 Server，统一管理该实例的项目、主管 Session 和专业 Session。添加项目或创建会话复用这个 Server，项目归属与记录分别保留。

用户通过选择或输入工作台运行环境中的既有目录添加项目。界面说明目录属于哪个运行环境；空目录可接入，但不会因添加项目自动生成应用代码。

同一实际目录已经接入时，打开原项目，保留会话和工作记录；同名但不同目录的项目分别显示，并能辨认其位置。添加目录不自动创建会话、启动开发或改写项目文件。目录不存在或不可访问时，明确说明原因。

重新打开时展示项目概况、主管会话、需求入口、未完成工作和待处理事项。用户选择继续哪个会话或工作，不自动重复投递此前指令。

## P-02 首次协作与项目知识入口

用户可以先只读查看、讨论和调查；专业帮助的 Plan 与报告保存在工作台，不要求先创建项目目录或向项目写文件。允许工作台写入项目前，需要用户明确同意该项目的写入使用。

首次正式保存或交付前，主管展示要建立的知识入口及项目补充规则：保留原有内容，只增加必要入口；已经存在的知识先识别和复用，冲突明确提出。用户确认差异后建立，失败说明未完成事项。此后的正常工作复用入口，不反复初始化。

已有权威正文在其他目录时，默认保留原位置，由固定知识入口引用，后续继续维护同一正文。确需迁移时，说明位置与引用变化，经用户确认后处理，不能同时保留两份并行权威定义。

空项目记录用户目标和未知；已有项目调查现有能力、文档和代码入口。观察到的实现不自动变成已确认需求或已经验证的能力。入口形成后，用户能查看当前概况、相关模块、需求与交付记录。具体组织规范见 [项目知识](project-knowledge.md)。

创建知识入口不需要先启动一个代码开发任务。用户只想讨论，可以保持只读，不能因此要求先完成全部知识整理。

## P-03 项目概况与关联入口

概况应让用户回答：这是哪个项目、目前具备什么能力、正在做什么、还有什么未知、下一步在哪里继续。

概况提供会话、待规划提案、实施需求、任务和知识入口。用户能从提案找到设计工作与拆分结果，从实施需求找到来源、依据及实现 Task，从任务找到计划、成果和报告，从知识找到相关需求、代码和测试入口。首次尚未调查的内容明确标为未知。

同一项目可以有多个主管会话，一个主管 Session 同时只推进一项未结束 Task，其他话题使用新主管 Session。专业 Session 的工作归入对应任务，可查看其结果和过程，不混入用户主管会话列表；需要用户处理的请求统一从主管交互入口呈现。会话的新建、选择和接续行为由 [主管对话](chief-conversation.md) 定义。

## P-04 切换、移动与持续使用

切换项目只改变用户当前查看的内容，不停止其他项目的工作。会话、需求、任务与报告必须保持项目归属，不能混入另一项目。

目录移动后，用户可以显式重新绑定原项目并保留关联记录。仍有工作正在修改该目录时，先处理正在执行的工作；引用资料找不到时明确指出，不能猜测替代文件。复制到另一目录作为另一个项目接入，不自动继承本环境的执行授权。

关闭浏览器或离开项目后，已启动工作继续。用户主动暂停或取消的含义见 [任务交付](delivery.md)。

## P-05 模型配置与首次使用

随产品交付安装、启动、取得访问凭证、进入浏览器工作台和停止工作台的使用说明。用户能够在首次使用时完成默认模型配置，并进行实际可用性检查。
模型配置以 Provider 为单位。Provider 有用户可改的显示名，以及创建后不变的技术标识；同一 Provider 下列出多个模型。接入端点时必须选定协议——OpenAI chat/completions、OpenAI responses、Anthropic messages——产品不按地址或名称猜测协议。已保存的 Provider 可以修改显示名、地址、协议、模型列表和凭证（凭证留空表示不改）；改名不使凭证引用、角色或项目指派失效；协议与地址不匹配时，以试连的真实结果告知，不显示为可用。


默认模型供各角色使用；既可以按角色设置全局取值，也可以针对某个项目调整。项目里既能设该项目的默认模型，也能只改其中一个角色。生效顺序是：项目内角色设置 → 全局角色设置 → 项目默认 → 默认模型；界面逐行标明当前值来自哪一层，已保存的设置可以恢复为默认（移除该层覆盖）。产品与技术设计使用统一设计角色，模型不必不同，但设计/实现作者与审核、测试保持独立 Session 和上下文；独立工作可按配置使用不同模型，不能仅凭模型不同宣称已消除幻觉。当前工作显示实际使用配置；更改不悄悄替换已经开始的工作。

配置无效或模型不可用时，提示具体原因和设置入口，保留用户输入与已有工作，不暗中改用另一个模型。没有模型时，已有项目、需求、知识、任务结果和文本文件仍可查看；讨论和执行明确提示暂不能进行。

凭证不出现在产品自身的读取面：对话记录中的产品事件与报告、项目知识、需求记录、任务成果和任何接口响应都只引用凭证、不返回其内容；模型的文件工具也不得读服务器私有存储（凭证、数据库与会话历史）。用户进入工作台需通过访问校验，退出后不能继续以已登录状态操作。

边界如实说明：Agent 的命令执行与操作者同权限，刻意绕过的 shell 仍可读到本机可读的任何文件——产品层面不承诺阻止这种情况，需要更强保证时按沙箱另立需求。

## P-06 查看项目资料

用户能浏览已接入项目的目录并阅读文本文件；从知识、需求和任务中的资料链接，能打开对应正文、计划、报告、证据和源码。查看不需要模型转述，也不等于修改文件。

界面说明文件所属项目和实际位置。文件不存在、不可读或内容不能展示时，给出原因，不显示空白假装没有内容。专业结果引用的资料也必须能定位；本环境没有保存的记录明确说明缺失。

首版必须提供目录与文本阅读、关联文件导航；通用文件编辑器、复杂媒体编辑不属于本模块的首版要求。
