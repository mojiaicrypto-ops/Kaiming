## 事实（来自运行中的 CharKeep 项目）

- `.dev/backlog.md` 的 B-1～B-11 由设计 Task `t-2dbe518eeb45`（design，settle，rework 2）产生，均带 `- 规格:` 引用；该 Task 未领取任何待办（`backlogIds=[]`），所以“设计中”为 0，它自己出现在“直接工作”。
- 看板把这类条目放进“就绪”，卡片标“待设计确认”（`awaitingDesign`）。用户截图时设计还没把 `- 规格:` 写回文件，条目按“无规格引用”落在“想法”；设计写入引用后即转“就绪”。分列由文件事实派生，无额外状态。
- 缺陷：`flowChain` 只看 `openTasks[0]`；待设计确认的切片没有未结束实施 Task，于是按 `ready` 退化成实施链（Plan 高亮），与卡片上的“待设计确认”自相矛盾。工作类型标签同样取 `openTasks[0]`，于是缺省显示。

## 改动

1. `webapp/src/project/project-model.ts`：新增 `activeWork(item)` = 未结束领取 Task，否则未结束的设计产出 Task；`flowChain` 与卡片工作类型用它。待设计确认的切片显示设计链（设计→审核→你确认→结算），并按产出 Task 的真实 phase 高亮（settle → 结算）。
2. `webapp/src/project/ProjectPage.tsx`：卡片只保留编号、两行标题、阶段链、一行元信息（工作类型 · 切片数 · 待设计确认/等你决定 · 返工 · 问题）；删除卡片内重复的切片编号清单（抽屉仍可看）。
3. `webapp/src/theme/base.css`：加宽内容区并放宽四列最小宽度；流程带改为轻量分隔行；卡片与列间距、标题层级、阶段链改为紧凑文本（完成/当前/计划三态），空列收窄。
4. 测试：`webapp/test/project-model.test.ts` 覆盖“待设计确认的切片显示设计链与真实阶段”和“未结束设计产出 Task 作为工作类型”；浏览器跑项目页现有用例并截图对比。
