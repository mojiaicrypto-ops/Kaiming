# P2-5 待办详情正文编辑器过小

状态：进行中（2026-11-18）
依据：U6 详情抽屉、BL-04「待办详情显示：正文、规格引用…」
验证档：`visual`（纯样式与容器宽度，无事件/状态/请求/数据变化）
现象：点击待办后右侧抽屉的“正文”只有 32px 高——`textarea` 复用了 `.inp` 的 32px 单行输入高度（实测 rows=6 仍是 32px），内容看不全；规格引用同样只有一行。抽屉固定 560px，正文区也偏窄。

## 改动

1. `.inp` 的 32px 只留给单行输入：新增 `textarea.inp { height:auto; min-height:96px; padding; line-height:1.6; resize:vertical }`。
2. 正文编辑器 `.backlog-body` 占抽屉主要高度：`min-height: max(240px, 34vh)`。
3. 待办详情抽屉加 `drawer-backlog`，宽 `min(760px, 94vw)`；≤560px 仍全宽。
4. U6 记录正文编辑器与抽屉宽度。

## 验收

- 1440×900：抽屉 760px，正文编辑框约 695×306，能读到正文段落；规格引用 96px。
- 390×844：抽屉全宽、正文约 357×287、无横向溢出。
- 现有 project 浏览器用例与 webapp 用例不回归。
