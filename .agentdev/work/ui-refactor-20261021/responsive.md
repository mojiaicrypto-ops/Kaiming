# 响应式：架构影响分析

问题：如果把"响应式"作为要求（桌面 + 窄屏 + 手机都能用），整体架构会不会变？
结论：**内核架构不变，外壳和渲染层增加一层"布局模式"抽象**。变的是 5 个地方，不变的是 7 个地方。

## 一、不变（内核）

| 层 | 为什么不受影响 |
|---|---|
| RPC / 会话流（prepare + SSE） | 传输与视口无关 |
| slot reducer（entryId 合并、增量、不去重丢失） | 纯数据 |
| normalize 边界 | 纯数据 |
| `session.respond` / `session.submit` / STOP | 服务端语义 |
| 任务模型（task / phase / member / result） | 服务端语义 |
| 需求记录与看板数据来源 | 服务端语义 |
| i18n 键表 | 语言与视口无关 |

## 二、要变的 5 处

### 1. 外壳组件多一个"布局"维度，而不是多一套组件

```
shell/
  TopBar.tsx        ← 1440 完整 / ≤860 收起项目名、导航保号
  StatusBar.tsx     ← 1440 四项 / ≤860 只留连接态 + 运行数
  AppLayout.tsx     ← 三态：desktop | compact | phone
  Drawer.tsx        ← ≥861 右侧抽屉 / ≤860 底部全屏 sheet
```

`AppLayout` 只判断视口并给上下文，页面组件内部不写媒体查询判断，靠 CSS 断点 + 少量布尔（`compact`）切换结构。

### 2. 会话左列（TUI 只在 ≤860 直接 `display:none`，且没有替代入口 → 真 bug）

| 视口 | 行为 |
|---|---|
| ≥861 | 240px 常驻左列 |
| ≤860 | 收进顶栏一个"会话"按钮 → 点击为全屏 sheet；当前会话名显示在顶栏 |

这是**必须补的设计**，否则手机上无法切换会话、无法新建会话。

### 3. 抽屉统一为"响应式抽屉"

| 视口 | 需求抽屉(560) / 成员抽屉(720) |
|---|---|
| ≥861 | 右侧固定宽 + scrim |
| ≤860 | 底部 sheet，高度 min(80vh, 内容)，圆角仅此一处例外或保持直角 |

### 4. 问题面板与 dock 在窄屏的可用性

TUI 的 dock 本来就是 `flex-direction: column`，窄屏可用；但需要补：
- `≤860` 时 composer 固定底部、`padding-bottom: env(safe-area-inset-bottom)`
- 软键盘弹出时：用 `visualViewport` 计算可用高度，避免 composer 被键盘遮住
- 问题面板选项行高度 ≥44px（触屏）

### 5. 界面语言之外再记一个"布局偏好"

- 外观页增加第三项：`密度`（舒适 / 紧凑）。TUI 是低密度；小屏自动紧凑。
- 存 localStorage，与主题、语言同组。

## 三、TUI 原型已有的断点（照抄，不新造）

| 断点 | 原型的处理 |
|---|---|
| `≤1100px` | 需求看板 4 列 → 2 列（可横向滚动） |
| `≤860px` | 会话左列隐藏；看板 1 列；设置左菜单变顶部横向；`.tx-in/.dock-in/.task-strip .in` 取消 90% 居中；`.mrow` 隐藏备注列；`.ask-h .f3` 隐藏 |
| `prefers-reduced-motion` | 动画时长归零 |

原型**没有**处理的（我们必须补）：手机上的会话切换入口、抽屉改 sheet、软键盘、顶栏溢出。

## 四、对既有代码的冲击

| 现有 | 冲击 |
|---|---|
| `state/*`、`api/*`、`lib/*` | 无 |
| `components/Transcript.tsx` | 无逻辑变化，只换类名与结构 |
| `components/InteractionCard.tsx` | 键盘交互改为"数字键直选 + ↑↓"，逻辑不变 |
| `MemberDrawer.tsx` | 从右侧抽屉变为响应式抽屉（外层容器变了） |
| `ChiefApp.tsx` | 拆为 `AppLayout` + `TopBar` + `StatusBar` + 各页；这是本轮最大改动 |

## 五、验证要求（响应式）

| 视口 | 必测 |
|---|---|
| 1440×900 | 三屏完整 |
| 1024×768 | 看板 2 列、侧栏仍在 |
| 860×700 | 边界：侧栏收起、菜单横置 |
| 390×844（手机） | 会话切换 sheet、抽屉 sheet、键盘不遮 composer、问题面板可答 |
| 320 宽 | 顶栏不溢出 |

每档用 Playwright 固定视口截图 + 关键交互脚本，作为验收证据。

## 六、代价

- 文件数：外壳由 1 个 `ChiefApp.tsx`（394 行）拆成约 6 个组件 + 1 个布局上下文。
- 新增依赖：0。软键盘用 `visualViewport`（原生 API）。
- 工期影响：会话屏 P1 增加约 15%（会话 sheet、软键盘、断点校准）。
