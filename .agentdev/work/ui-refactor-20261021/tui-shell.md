# 外壳核对（TUI，以原型为准）

来源：`docs/design/tui/app.js` / `chat-*.js` / `data.js` / `tui.css`。
壳代码一律不看。本文只记录**原型里真实存在**的布局、区域与交互。

## A. 全局外壳（三屏共用）

```
┌ top(44px) ─────────────────────────────────────────────────────────┐
│ AgentDev │ [payments-api ▾] │ 会话 需求 设置 │        ● 已连接      │
└────────────────────────────────────────────────────────────────────┘
│                     view 内容（占满剩余高度，可滚动）                │
└ status(28px) ──────────────────────────────────────────────────────┘
│ /home/dev/work/payments-api │ ⎇ main │ ● 2 个 Agent 运行中 │ 1/2/3 切换 · i 输入 · Esc 关闭 │
└────────────────────────────────────────────────────────────────────┘
```

| 区域 | 内容 | 交互 |
|---|---|---|
| `brand` | 字标 "AgentDev" | — |
| `proj` | 当前项目名 + ▾ | 打开"切换项目"对话框 |
| `nav` | 会话 / 需求 / 设置 三个文字标签 | 当前项 `aria-current="page"`；会话标签带 `◆N` 待决定角标；快捷键 1/2/3 |
| 右侧连接态 | `● 已连接` / `● 重连中` | 状态符号制 |
| 状态栏 | 项目路径、Git 分支、运行中 Agent 数、快捷键提示 | 纯文本 |

## B. 会话页布局

```
┌ sessions(240) ┬ conv ──────────────────────────────────────────────┐
│ 主管会话      │ banner（断线 / 阻塞，按住时才出现）                 │
│ ● 密码重置    │ task-strip（任务条，无任务时 hidden）               │
│ ◆ 支付网关设计│ ┌ tx（转录，可滚，内容宽 90% 居中）──────────────┐ │
│ ○ 通知偏好讨论│ │                                                │ │
│ ✓ 结算按钮文案│ │                                                │ │
│ ＋ 新建会话   │ └────────────────────────────────────────────────┘ │
│               │ dock：jump / pop(问题面板) / queue / composer / hint│
└───────────────┴────────────────────────────────────────────────────┘
```

| 区域 | TUI 实际内容 |
|---|---|
| 会话左列 | 标题"主管会话" + 逐条会话（状态符号 + 标题）+ 底部"＋ 新建会话" |
| banner | 仅两类：`连接已断开，正在重连`（附"重连后从快照合并，正在输出的内容不会丢"）、`blocked` 代码 + 详情 + "知道了" |
| task-strip | `taskId` + 阶段链（`✓ 计划 ─ 开发 ─ 审核 ─ 测试 ─ 结算`，当前阶段高亮）+ 成员 N ▴▾ + 状态 + 暂停/继续 |
| 转录 | 空态才有 logo + 三个示例问题；否则消息流 |
| jump | "↓ 回到最新"，仅在离底时显示 |
| pop | 问题面板（详见 D） |
| dock | 排队消息行（含"撤回"） |
| composer | `❯` + 两行 textarea |
| hint | 快捷键提示 |
| drawer | 成员会话只读抽屉（详见 E） |

## E. 问题面板（dock 上方，非遮罩）

| 能力 | 行为 |
|---|---|
| 位置 | dock 上方，不覆盖转录 |
| 一次性 | 一次只显示一个，`2/3` 计数 |
| 来源 | `来源 · T-xxxx / 阶段` |
| 选项 | 行 + 数字键 `1..n`；`↑↓` 选择；`Enter` 确认；`Esc` 稍后 |
| select | 选项 + "输入其他答案…" |
| confirm | "确认 / 拒绝" |
| input | 单行输入，Enter 提交，留空用默认 |
| 已回答 | 卡片转 `done`：`答复已收到：X` + "已交给 X，执行结果会单独报告" |
| 上一条 | 顶部显示上一条的答复摘要 |
| 收起 | 折叠成 `◆ N 个问题等待回答 · 打开 ›` |
| 草稿 | 同一问题输入内容保留；换题清空 |
| 焦点 | 新问题首次自动聚焦（用户正在输入则不抢） |

## F. 需求页

```
需求页头：h1"需求" + 副标题"提案先设计，实施需求可以直接实现"
通知行：✗ 1 个需求文件无法解析：路径 … 查看
四列看板：提案 / 待实现 / 进行中 / 已完成（列头带计数，空列显示"暂无"）
卡片：id / 标题 / 状态符号
```

抽屉（右侧，紫左边框）：

| 字段 | 提案 | 实施需求 |
|---|---|---|
| 头部 | `id · 提案` + 标题 | `id · 实施需求` + 标题 |
| 状态 | ✓ | ✓ |
| 意图 / 目标 | 意图 | 目标 |
| 验收 | — | 列表 |
| 来源 | ✓ | ✓ |
| 未知 | ✓ | — |
| 完成摘要 | — | ✓（仅已完成） |
| 底部动作 | 打开设计会话 / 委托设计 | 实现 / 打开会话 |

无法解析文件：显示路径、行号、原因、原文，动作"让主管修复"。

## G. 设置页

```
┌ menu(左) ┬ set-pane ─────────────────────────────┐
│ Providers│ h1 + 说明一句话                       │
│ 角色模型 │ set-body（表单）                      │
│ 外观     │                                       │
└──────────┴───────────────────────────────────────┘
```

| 页 | 内容 |
|---|---|
| Providers | 每行：名称 + 状态、base URL、模型列表、`试连` 按钮；底部 `＋ 添加服务` |
| 角色模型 | 顶部 `全局 / 本项目` 分段开关；每行：角色名 + 模型下拉 + 来源标记（`全局` / `继承全局` / `本项目覆盖`） |
| 外观 | 主题：`深色 / 浅色` 分段 |

## I. TUI 未定义、但产品与现有实现需要的外壳能力

| 项 | 原因 | 最小处理（沿用 TUI 词汇） |
|---|---|---|
| 语言切换 | 用户要求多语言；TUI 只有主题 | 外观页加"语言"行，与主题同组 |
| 登录 / 凭证 | TUI 无 | 独立最小页，沿用同一套令牌 |
| 历史读取警告 | 现有实现有，TUI 无 | banner 增加第三类"历史读取警告"，可展开 |
| 离线态 | TUI 只有两态 | 连接态扩为连接中/已连接/重连中/离线 |
| 项目列表 | 无 `project.list` | 对话框用本地最近记录 + 手动输入路径 |
